# Rust shell agent guide

Applies to everything under `app/src-tauri/`. Root rules in `../../AGENTS.md` also apply. The maintainer does not know Rust: keep the surface small and stable, and explain every change in plain English in the PR.

- **Scope:** app lifecycle and narrowly scoped commands only. No business logic about tools or versions.
- **No shell plugin.** Never give the webview a way to spawn arbitrary processes. Add one scoped command per feature (scan, get state, refresh, open the uv install guide, open containing folder, open config file). Existing commands: `get_state`, `get_preferences` (the preferences answer, read only; docs/app/preferences.md), `refresh`, `open_uv_docs` (no arguments, one fixed URL), `open_containing_folder` (one path, validated in `src/reveal.rs`; Explorer selects it and never runs it). Copying text is done in the webview with `navigator.clipboard`, so there is no clipboard command or plugin.
- **Opaque JSON.** Hold the current and previous scan results as raw JSON, check only `schema_version`, never deserialize deeper. Diffing and sorting belong to the UI.
- **Tray and menu** are created at launch and must survive webview reloads and crashes. Left-click toggles the popup; the full menu offers Refresh, Show versions, Open config file, Start with Windows (off by default), About, Quit. It is built incrementally: Show versions and Quit first (ticket 20), Refresh (ticket 24), the full menu by ticket 27. Refresh must work without the webview.
- **Popup:** frameless, about 380x540, anchored above the tray, hides on focus loss, recreated if the webview dies.
- **Plugins:** autostart, single-instance, positioner and updater only.
- **Scan command:** locate uv (PATH, then `UV_INSTALL_DIR`, then default user-local bin); run the bundled core with frozen dependencies, a uv-managed Python only, and the project environment in the app data folder; fixed arguments `list --json`; 30 s timeout, 180 s on first run; capture stderr; report one of uv missing, setting up, failed (with stderr), ok. The uv path must be injectable for tests.
- **Two fixed core invocations only:** the scan above and the preferences query (added by ticket 12a). Rust never parses TOML and never accepts arbitrary arguments. The update-check flag and the config file path come from the preferences query, not from Rust reading config.
- **Never install anything** (including uv) on the user's behalf.
- **Updater:** check at startup and every 24 h unless disabled (the flag comes from the preferences query); install only after the user confirms. Update metadata is signed with the Tauri updater key; the installer itself is unsigned in v1.
- **Checks:** rustfmt, `clippy -D warnings`, cargo-deny, tests (`npm run lint:rust`, `npm run test:rust`). Test scan and state commands with a fake `uv`; do not unit test tray or window behaviour.
- **Capabilities:** `capabilities/default.json` grants the popup webview one permission per scoped command, nothing else. `tests/capabilities.rs` fails on any permission not in its reviewed list, and `deny.toml` bans `tauri-plugin-shell`; widen either only deliberately and explain it in the PR.
- **Names:** the crate is deliberately called `tray-shell`; the product name comes from `productName` in `tauri.conf.json` (read at runtime via `package_info()`), and the app version from `version` in `Cargo.toml`. `tests/product_identity.rs` checks both against the core and the UI constant. The UI constant (`app/src/product.ts`) is generated from `productName` by `npm run gen` and drift-checked by `npm run lint:gen`; the Rust test stays as a second guard.
